# INT-005 — Text interview turns

The student interview page is the INT-004 session screen at `/interview/session/:id`. This task adds the conversation, countdown, and end action on that screen. The catalog at `/interview` is unchanged.

The browser never calls the AI provider. It sends the signed-in student's JWT to the `interview-turn` Edge Function.

## Request

`POST /functions/v1/interview-turn`

```json
{
  "sessionId": "uuid",
  "answer": "The student's answer",
  "clientTurnId": "uuid"
}
```

`sessionId`, a non-empty `answer`, and `clientTurnId` are required. The browser creates one UUID per send and keeps it if that send fails, so a retry is the same answer. The key is stored on the student row only after the reviewed migration below is applied. Until that column exists, do not deploy this function: it selects `client_turn_id`.

## Success response

```json
{
  "assistantMessage": "The follow-up question",
  "replayed": false,
  "turns": [
    {
      "id": "uuid",
      "role": "user",
      "content": "The student's answer",
      "seq": 1,
      "createdAt": "2026-10-27T08:00:00.000Z"
    },
    {
      "id": "uuid",
      "role": "assistant",
      "content": "The follow-up question",
      "seq": 2,
      "createdAt": "2026-10-27T08:00:01.000Z"
    }
  ]
}
```

`role` is only `user` or `assistant`. `seq` is the chronological order.

## Error response

```json
{ "error": "A short message safe to show the student", "code": "SESSION_EXPIRED" }
```

Codes include `UNAUTHORIZED`, `FORBIDDEN`, `NOT_FOUND`, `INVALID_INPUT`, `SESSION_CLOSED`, `SESSION_EXPIRED`, `TURN_CONFLICT`, `AI_NOT_CONFIGURED`, `INTERVIEW_AI_TIMEOUT`, `INTERVIEW_AI_RATE_LIMIT`, `INTERVIEW_AI_UNAVAILABLE`, and `NOT_SAVED`.

A missing session and another student's session both return `NOT_FOUND`. The function does not return template prompts, other students' turns, or provider errors.

## Secrets

Set these as Supabase Edge Function secrets. Do not put them in Angular `environment.ts`.

| Name | Required | Value |
| --- | --- | --- |
| `INTERVIEW_AI_PROVIDER` | No | `openai` or empty. Any other value is rejected. |
| `INTERVIEW_AI_MODEL` | No | `gpt-6-luna`. Used when this secret is empty. |
| `OPENAI_API_KEY` | Yes | OpenAI API key. Function secret only. |
| `INTERVIEW_AI_TIMEOUT_MS` | No | Default `45000` |
| `INTERVIEW_AI_MAX_RETRIES` | No | Extra attempts after the first call. Default `2` |
| `INTERVIEW_AI_RETRY_BASE_MS` | No | Default `1000` |

`supabase/functions/env.example` lists the same names with an empty key. For local serving, copy it to `supabase/functions/.env` and fill the key there. That file is gitignored.

Dashboard: Project Settings → Edge Functions → Secrets, or:

```bash
supabase secrets set --env-file supabase/functions/.env
```

Deploy only after review. Keep JWT verification enabled for `interview-turn`.

OpenAI `gpt-6-luna` is the v1 model, called at `POST https://api.openai.com/v1/chat/completions`. See `docs/interview/AI_PROVIDER.md`.

## Authorization

1. The function reads the user from the bearer JWT. It ignores any user id in the body.
2. It calls `has_permission('interview.access')`, the same database rule as the Angular route guard.
3. It loads `interview_sessions` with the user JWT, then checks `user_id`.
4. After those checks, the function inserts the student turn and the assistant turn together with the service role. A provider failure inserts nothing. The service role is also used to read `system_prompt` and `duration_minutes` when a published-template policy hides the template. The prompt is not returned to the browser.
5. Students may still insert their own `user` turns through the Data API while the session is `in_progress` and inside its duration. They cannot insert `assistant` turns, and they cannot update or delete saved turns. The read policy still limits them to their own sessions.
6. Angular selects `title`, `kind`, and `duration_minutes` for the session. It does not select `system_prompt`.

## Turns and retries

The function looks up `clientTurnId` before calling the provider. A saved student row with the following assistant row is returned as `replayed: true` and the provider is not called again. A saved student row with no later turn is repaired with one assistant row. A saved student row that already has a later turn, but not its assistant reply, returns `TURN_CONFLICT`.

Before calling OpenAI, the function inserts one `interview_turn_claims` row for `(session_id, client_turn_id)`. That primary key is the lock across function instances. The owner calls OpenAI. A second request with the same id waits (`TURN_IN_PROGRESS`) and does not call OpenAI. A retry after the turns are saved returns the saved reply. If the provider fails, the claim is marked `failed` and no turn is inserted. If the provider succeeds and the turn insert fails, the assistant text stays on the claim and a retry saves it without a second provider call. A claim still marked `processing` after two minutes can be taken over. A different `clientTurnId` is a different answer and gets the next free `seq`. A retry after the session is completed or expired returns the saved reply when it exists, and is rejected when it does not.

The same wording can be saved again when the key is different. The browser keeps `clientTurnId` until the send succeeds.

`overall_score` is not written. Ending a session sets `status` to `completed` and `ended_at`. The database trigger already rejects score changes and changes to a finished session.

## Timer

Remaining time is `started_at + duration_minutes` from the session and its template. Refreshing the page reads those stored values again. The HR seed template is 20 minutes. The browser clock only hides the answer box and shows the warning. It does not mark the session complete. Completion is written when the student confirms End Interview, or when the Edge Function receives an answer at or after the server's end time. The function also rejects answers for a session that is already `completed` or `failed`.

## Manual HR interview

This path was not run against the shared database in the implementation pass. Do not create a permanent test student.

1. Apply the migration, set `OPENAI_API_KEY` and `INTERVIEW_AI_MODEL=gpt-6-luna`, then deploy `interview-turn`.
2. Sign in as a student who has the Allowed Interview label (`interview.access`).
3. Open `/interview`, start **HR Behavioral Interview**, and confirm the timer is 20:00 and does not reset on refresh.
4. Ask for the first question, send a second answer, and confirm both pairs appear in order.
5. In the SQL editor, read only that session's rows from `interview_turns` and confirm `role`, `content`, and `seq`.
6. End the interview from the confirmation dialog and confirm `interview_sessions.status` is `completed`.
7. Confirm another answer is rejected.
8. Repeat the request without a JWT, with a student who lacks `interview.access`, and with another student's session id. Expect `401`, `403`, and `404`.

## Schema

`supabase/migrations/20261027_interview_turn_security.sql` was applied to project `yllfccuxohnipleyseup` with the single-migration API. `supabase db push` was not used, because other local migration files are not in that project's migration history. Deploy `interview-turn` only after `OPENAI_API_KEY` is set as a function secret.

The file adds `client_turn_id` on student rows, a partial unique index on `(session_id, client_turn_id)`, and a before-insert trigger. The trigger rejects a turn when the session is missing, owned by someone else, not `in_progress`, or past `started_at + duration_minutes`. A student insert with `role = assistant` is also rejected. The service role may insert both roles, and status and expiry still apply to it. The function reads the template as `SECURITY DEFINER` with `search_path = public` because a student cannot read an unpublished template. It returns no row contents. Missing and not-owned sessions raise the same error.

The old insert policy is dropped and replaced with one policy: `role = user`, owned session, `status = in_progress`. The student update and delete policies are dropped, and `UPDATE` and `DELETE` are revoked from `authenticated`. The select policy is unchanged. Deleting a session can still cascade to its turns because the foreign key bypasses row security. The app does not expose session delete.

The migration is applied. The Angular page does not select `client_turn_id`. `supabase/tests/int_005_turn_guard.sql` has not been executed against fixture users.

Scoring after the session is completed is INT-008 (`docs/interview/INT-008.md`). `interview-turn` still does not write `overall_score`.
