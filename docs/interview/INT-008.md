# INT-008 — Interview evaluation and results

Evaluation runs after an INT-005 session is completed. The browser never calls the model and never sends a score. `interview-evaluate` reads the saved transcript, asks the existing OpenAI configuration for a JSON scorecard, and `apply_interview_evaluation` stores the result.

The current evaluation version is `INT008-v1`. A completed session keeps that version and its score rows. A later rubric version must not overwrite them.

## Data model

`interview_scores` already existed from INT-002. This task adds `evidence` and `created_at`. The competency explanation is the existing `rationale` column. The unique key remains `(session_id, competency, eval_version)`.

`interview_sessions` already had `overall_score`. This task adds:

| Column | Meaning |
| --- | --- |
| `evaluation_status` | `pending`, `processing`, `completed`, or `failed`. Null means evaluation has not started. |
| `eval_version` | Version that produced the stored score. Set only when evaluation completes. |
| `evaluated_at` | When the scorecard was stored. |
| `evaluation_summary` | Short overall assessment. |
| `evaluation_strengths` | JSON array of short observations. |
| `evaluation_improvements` | JSON array of actions for the candidate. |
| `evaluation_claimed_at` | Claim timestamp. A second request waits while this is less than three minutes old. |

`overall_score` is the unweighted arithmetic mean of the competency scores stored for that session and `eval_version`, rounded to 2 decimal places. Competencies the model marks `applicable: false` are not inserted and are not included in the mean. The model’s own overall score is ignored.

A completed evaluation must have `overall_score`, `eval_version`, `evaluated_at`, and `evaluation_summary` together. The interview `status` stays `completed` when evaluation fails.

## Competencies

If `interview_templates.rubric_json` has a competency list, those labels are the scorecard. The published HR template scores Communication, Teamwork, Problem solving, and Decision making. The published technical template scores Programming, Data structures, Algorithms, and Problem solving.

If the rubric has no competencies, the fallback depends on `kind`:

- HR: Clarity, Communication, Problem Solving, Confidence / Professionalism
- Technical: Clarity, Technical Knowledge / Depth, Problem Solving, Communication
- Domain: Clarity, Technical Knowledge / Depth, Communication, Problem Solving, Confidence / Professionalism

The model must use those names. It must mark a competency not applicable when the transcript does not contain evidence. It must not infer face, voice, or body language, must not punish questions that were never asked, and must not treat a long answer as a strong answer.

## Edge Function

`POST /functions/v1/interview-evaluate`

```json
{ "sessionId": "uuid" }
```

Any score or feedback in the body is ignored.

Success:

```json
{
  "status": "completed",
  "preserved": false,
  "evalVersion": "INT008-v1",
  "overallScore": 70,
  "summary": "Short assessment",
  "strengths": ["Specific observation"],
  "improvements": ["Specific next step"],
  "evaluatedAt": "2026-11-05T08:13:00.000Z",
  "competencies": [
    {
      "competency": "Communication",
      "score": 70,
      "feedback": "What worked or what to change",
      "evidence": "What the transcript showed"
    }
  ]
}
```

`preserved: true` means the session was already completed under a different version. The function returns that saved scorecard and does not call the model.

Errors use `{ "error": "message safe for the student", "code": "CODE" }`.

| Code | Status | When |
| --- | --- | --- |
| `UNAUTHORIZED` | 401 | Missing or invalid user JWT |
| `FORBIDDEN` | 403 | Signed in, without `interview.access` |
| `NOT_FOUND` | 404 | Missing session, or a session owned by someone else |
| `SESSION_NOT_COMPLETED` | 409 | Session is not `completed` |
| `EMPTY_TRANSCRIPT` | 422 | No saved turns |
| `INCOMPLETE_TRANSCRIPT` | 422 | Missing a question or an answer |
| `TRANSCRIPT_TOO_LARGE` | 422 | Transcript is over 100,000 characters |
| `EVALUATION_IN_PROGRESS` | 409 | Another request holds a fresh claim |
| `AI_NOT_CONFIGURED` | 503 | Provider secret is missing or not OpenAI |
| `INTERVIEW_AI_TIMEOUT` | 504 | Provider timed out |
| `INTERVIEW_AI_RATE_LIMIT` | 429 | Provider asked the function to slow down |
| `INTERVIEW_AI_UNAVAILABLE` | 503 | Provider failed |
| `INVALID_EVALUATION` | 502 | Model JSON failed validation |
| `NOT_SAVED` | 500 | The scorecard could not be stored |

Authorization matches INT-005. The function reads the user from the bearer JWT, checks `has_permission('interview.access')`, and loads the session with that user’s client. The service role is used only after those checks, to claim the evaluation, read the template rubric and interview context, and write scores. The template prompt is not returned.

A completed scorecard is returned without another model call. A failed or stale claim can be taken again. A provider or JSON failure marks `evaluation_status` failed and leaves the interview `completed`. Invalid JSON does not insert scores. The apply function inserts with `ON CONFLICT ON CONSTRAINT interview_scores_session_competency_version_unique DO NOTHING` and rejects a different score for a row that already exists. The constraint columns are still `(session_id, competency, eval_version)`. The constraint name is used because `eval_version` is also a function output and cannot be named in `ON CONFLICT (column list)`.

Provider secrets are the INT-005 secrets: `OPENAI_API_KEY`, optional `INTERVIEW_AI_PROVIDER=openai`, `INTERVIEW_AI_MODEL=gpt-6-luna`, and the same timeout and retry settings. `interview-turn` is unchanged.

## Student flow

1. End Interview still calls `finish_own_interview_session`.
2. The session is `completed` before evaluation starts.
3. The app requests `interview-evaluate` and opens `/interview/session/:id/result`.
4. The results page reads the saved session, the competency rows for `eval_version`, and every turn ordered by `seq`.
5. While `evaluation_status` is `processing`, the page re-reads the database every 2.5 seconds for up to 45 seconds. That polling does not call the model.
6. A failed evaluation shows the transcript and a Retry evaluation action. Retry is the only automatic way to call the model again.

The same redirect happens when the timer finishes the session. Opening the result URL directly starts evaluation once if it has not started. Refreshing a completed result does not call the model.

The page has loading, processing, timeout, failed, retry, not found, unauthorized, empty transcript, incomplete transcript, and network states. Bars use the saved scores. The transcript is the full saved text.

## Security

Students can read score rows only for their own sessions. The existing read policy is kept. There is no insert, update, or delete policy for `authenticated` on `interview_scores`, and those privileges are revoked. A trigger rejects student score writes and rejects any update to a stored score, competency, rationale, evidence, or version.

Students cannot update `overall_score` or the new evaluation columns. The migration revokes column update on those fields, and the session guard rejects the change when a statement reaches the row. Local checks confirmed the guard raises `overall_score is written by the evaluator` and `interview evaluation is written by the evaluator`.

`claim_interview_evaluation`, `fail_interview_evaluation`, and `apply_interview_evaluation` execute only as `service_role`. They refuse every other role. Admins do not gain a new path to another student’s transcript. Interview reads stay owner-scoped, which is the existing session model.

INT-005 turn policies are not dropped.
