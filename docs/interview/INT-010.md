# INT-010: Personalized practice tips

Practice tips are stored on the INT-008 evaluation snapshot. `interview-evaluate` still scores the transcript, computes the overall score as the unweighted mean of applicable competency scores, and then adds 3–5 tips for the lowest-scoring applicable competencies. The evaluation version remains `INT008-v1`.

## Database

`supabase/migrations/20261107_interview_practice_tips.sql` adds nullable `interview_sessions.evaluation_tips text[]`.

- Existing completed evaluations stay valid with `evaluation_tips` null.
- A non-null value must contain 3–5 distinct, trimmed, non-empty tips of at most 400 characters. `interview_tips_valid(text[])` enforces that check.
- The INT-008 7-argument `apply_interview_evaluation` is unchanged.
- New evaluations call the 8-argument overload, which writes `evaluation_tips` in the same update as the scorecard.
- A repeated call for the same version returns `already_completed` and the stored tips. It does not write a second score row or replace the tips.
- Students cannot update `evaluation_tips`. The session guard rejects the change, and `UPDATE` on that column is revoked from `PUBLIC`, `anon`, and `authenticated`.
- Only `service_role` can execute the 8-argument apply function. The function still requires `interview_evaluation_is_trusted()`.
- Owner read policies are unchanged. A student can read tips only on sessions they own.
- The guard still blocks student writes to the other evaluator columns. It checks `template_version_id` only when that column exists, so an older local database does not break and a database that has the INT template-version column still rejects a change to it.

Do not apply this file with `supabase db push`. Do not apply it to project `yllfccuxohnipleyseup` without explicit approval.

## Tip generation

After `parseEvaluationPayload` accepts the scorecard:

1. Applicable competencies are sorted by score, lowest first. A competency the model marked not applicable is stored with a negative score and is excluded.
2. The model may return a `tips` array in the same JSON object. Entries are trimmed, empty entries are dropped, and case-insensitive duplicates are removed.
3. The list is used only when 3–5 tips remain, none of them repeat a strength or improvement, and at least two refer to a token from the lowest half of the applicable competencies, their feedback, or their evidence.
4. Otherwise the function stores deterministic fallback tips for that lowest half. Each tip names the competency and a concrete practice action, such as the STAR method, time and space complexity, a specific example, or a step-by-step decision. N/A competencies are not named.
5. A successful new evaluation always sends 3–5 tips. The database rejects any other array.

An already completed snapshot is returned as stored. This task does not invent tips for older rows whose `evaluation_tips` value is null.

## Edge Function

`supabase/functions/interview-evaluate/index.ts` reads and returns `evaluation_tips`. The response includes `tips`. For a newly completed evaluation, an empty tip list is treated as not saved. For an older completed evaluation, `tips` is an empty array and the rest of the scorecard is unchanged.

Authentication, session ownership, the completed-session requirement, claim, failure, retry, idempotency, and the overall-score calculation are unchanged.

## Scorecard

The result page shows **Your Next Steps** only after a successful scorecard load when 3–5 tips were saved. The subtitle is “Personalized recommendations based on your interview performance.” Tips are numbered cards, separate from Strengths and Areas for improvement. Loading, processing, and retry states do not show tips. A refresh reads `evaluation_tips` through `getOwnEvaluation`. An older snapshot with no tips still shows the score, competencies, notes, and transcript.

## Known limitations

- Evaluations completed before this column was filled keep `evaluation_tips` null. The page hides Your Next Steps for those rows instead of inventing tips.
- A completed evaluation is not scored again, so tips are not backfilled.
- Fallback tips are specific to the weak competencies and their saved evidence. They are not a second model judgment.
- The Angular result query selects `evaluation_tips`. The app should not be deployed until this migration is applied to the database it reads.
- The local `ulearn-int012-local` database now has the column and the updated guard. That change was not made on project `yllfccuxohnipleyseup`.
